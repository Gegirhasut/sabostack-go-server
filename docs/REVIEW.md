# Внешнее ревью (12.11.2026)

Ревью коммита `b37f934`, оценка 8.5/10. Я проверил каждое замечание по коду. Все пять
«косяков» и две мелочи подтвердились, их исправления — в коммите после `b37f934`. На каждое
подтверждённое замечание есть тест (`internal/*/review_test.go`, тесты `TestReview*`),
который падает на `b37f934` и проходит после исправления. Два теста используют новый API
(`TrustedProxies`, `Leaving`), поэтому на старом коде не компилируются. Подмена IP на
старом API воспроизведена отдельным тестом: старый код вернул `1.2.3.4` из подделанного
заголовка.

## Второй раунд (13.11.2026)

Ревью коммита `3e22b3c`, оценка 9/10. Ревьюер проверил исправления первого раунда по
краевым случаям: реконнект внутри тика, `RoundEnd`, `Restore`, запас fencing (~2,5 с при
аренде 10 с), истечение claim перед публикацией, падение после `Leaving`. Претензий к ним
нет. Нашлись три новые проблемы, две из них были и в `b37f934`. Все подтвердились. Тесты
падают без исправления и проходят с ним.

| # | Замечание | Подтвердилось? | Исправление | Тест |
|---|---|---|---|---|
| 1 | `handleWS` делает `conns.Add` после `Upgrade`, параллельно с `conns.Wait` в `Shutdown`. Race detector ловит это примерно раз на шесть прогонов. | Да, и хуже: тест воспроизводит data race с первого прогона, а соединение принималось **уже после** возврата `Shutdown`. | Обработчик регистрируется до upgrade под мьютексом, а `Shutdown` под тем же мьютексом закрывает вход и только потом ждёт. Опоздавшие получают 503, метрика `connections_rejected_total{reason="shutting_down"}`. | `TestReviewShutdownDuringUpgrades` (20 раундов: 8 клиентов подключаются, пока идёт `Shutdown`) |
| 2 | Окно между проверкой `fenced` и `mgr.Adopt`: усыновлённый матч мог запуститься на только что изолированном узле и остаться зомби, потому что его записи падают с обычной ошибкой Redis, а не с `ErrNotOwner`. | Да | Изоляция (`fenced` + `EvictAll`) и запуск усыновлённых матчей (проверка + `Adopt`) взаимно исключены мьютексом. Под ним нет ввода-вывода, поэтому изоляция не ждёт. Пока узел изолирован, каждый неудачный heartbeat повторяет `EvictAll`. Это страховка для `Restore`, который мог начаться до повторной потери аренды: держать его под мьютексом нельзя, он ходит в Redis. | `TestReviewMatchStartedWhileFencedIsStopped` |
| 3 | Заявку сняли, игрок ушёл, назначение потерялось: `waiter` навсегда оставался в `m.waiting`, и раз в секунду по нему уходил лишний `LRem`. | Да | Для ушедшего игрока, чья заявка уже снята, вызывается `popped()`. Записанное назначение доставляется, и `deliver` забывает `waiter`. Назначение, которое уже не придёт, просто забывается, без повторной постановки. Если хозяин жив, ждём дальше. | `TestReviewGoneTicketAfterPopIsForgotten` |
| м | При `-trusted-proxies > 0` порт сервера нельзя открывать напрямую: клиент в обход прокси снова подделает заголовок. | Да | Пункт добавлен в [чеклист продакшена](../README.md#чеклист-продакшена). | — |
