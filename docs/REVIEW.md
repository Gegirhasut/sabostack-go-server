# Внешнее ревью (12.11.2026)

Ревью коммита `b37f934`, оценка 8.5/10. Я проверил каждое замечание по коду. Все пять
«косяков» и две мелочи подтвердились, их исправления — в коммите после `b37f934`. На каждое
подтверждённое замечание есть тест (`internal/*/review_test.go`, тесты `TestReview*`),
который падает на `b37f934` и проходит после исправления. Два теста используют новый API
(`TrustedProxies`, `Leaving`), поэтому на старом коде не компилируются. Подмена IP на
старом API воспроизведена отдельным тестом: старый код вернул `1.2.3.4` из подделанного
заголовка.

| # | Замечание | Подтвердилось? | Исправление | Тест |
|---|---|---|---|---|
| 1 | IP берётся из **первого** адреса `X-Forwarded-For`, который пишет сам клиент: так обходится `-max-conns-per-ip` | Да | Флаг `-trust-proxy` заменён на `-trusted-proxies N`. IP берётся N-м адресом **справа**, то есть тем, который записал наш крайний прокси. Учитываются повторённые заголовки, IPv6 и мусор (на мусоре IP берётся из TCP-соединения). | `TestReviewForwardedForIsReadFromTheRight` |
| 2 | После переподключения у игрока на длину паузы больше времени до idle-форфита | Да: после 15 с отсутствия форфит наступал через 45 с вместо 30. Кроме того, **замена сокета без единого хода** каждый раз сбрасывала таймер, и бездействующий игрок мог не проиграть никогда. | `Attach` больше не трогает `LastInput`: сдвиг по окончании паузы и `Restore` (матч после падения стоит на паузе) уже учитывают время отсутствия. | `TestReviewReconnectAddsIdleCredit`, `TestReviewReplacingConnectionResetsIdle` |

| 5 | При штатном выключении игроков на короткое время отправляют на умирающий узел | Да | Перед закрытием сокетов узел помечает свой `alive`-ключ как «уходящий». Заявку он ставит заново, только если хозяин мёртв и ничего не записал, то есть когда назначение уже не может прийти. | `TestReviewLostAssignmentMessageIsRecovered`, `TestReviewLiveClaimerIsNotRequeuedDeadOneIs` |
